# Goule UI 调研与推荐方向

> 调研日期：2026-08-29  
> 目标：为本地 Dashboard 选择一套既有开发者工具质感、又不制造生产力焦虑的视觉语言。

## 1. 设计命题

Goule 不是工时监控大盘，也不是另一个 productivity score。它的界面首先要回答：

> 我今天做了什么，这些证据够不够让我安心收工？

因此 UI 必须同时满足四件事：

1. **结论先于图表**：用户 3 秒内看到今天的状态，而不是先读一屏指标。
2. **证据可审计**：repo、branch、session、commit 和时间块能逐级展开。
3. **压力不被游戏化**：不展示“压力 78 分”、红色告警墙或惩罚性 streak。
4. **双模同源**：核验与日报只是同一份 DayFacts 的两种排版，不是两套产品。

## 2. 参考产品拆解

| 参考 | 值得借鉴 | 不应照搬 |
| --- | --- | --- |
| [Linear](https://linear.app/) | 深色表面、克制层级、极细分隔线、快捷操作的精致感 | 过度冷峻会让 Goule 像项目管理工具，缺少“允许下班”的情绪出口 |
| [Raycast](https://www.raycast.com/) | 开发者熟悉的 command palette 语言、聚焦态、键盘优先 | 大面积红黑高对比太兴奋，不适合一天结束时的安静场景 |
| [WakaTime](https://wakatime.com/) | 编码时间线、项目归因、编辑器上下文 | 图表与饼图过多，容易把“事实”变成 KPI 竞赛 |
| [ActivityWatch](https://activitywatch.net/) | Local-first、原始数据透明、活动块可追溯 | 信息架构偏工具后台，视觉密度高且缺少主叙事 |
| [RescueTime](https://www.rescuetime.com/) | 日历时间轴、活动分类、工作节奏回看 | productivity score 与“优化自己”的语气不符合反 PUA 立场 |
| [Oura](https://ouraring.com/) | 把恢复状态翻译成人话；建议是照顾用户，而不是督促用户 | 健康产品的圆环和生活方式摄影不属于开发者证据工具 |

### 调研结论

- WakaTime / ActivityWatch 证明“时间轴 + 归因”是可信证据的最佳载体。
- Linear / Raycast 证明开发者工具可以高密度而不杂乱，关键是层级、字体和聚焦态。
- Oura 最值得借鉴的不是圆环，而是叙事方式：**把恢复信息写成今天可以少做一点的理由**。
- Goule 不应使用生产力分数环、排行榜、连续打卡火焰、满屏红绿 KPI。

## 3. 三个候选方向

| 方向 | 视觉关键词 | 优点 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| A. Command Center | 近黑、冷灰、紫蓝、紧凑表格 | 很“开发者”，实现成熟 | 像 Linear 插件；让下班核验仍像在工作 | 不选 |
| B. Recovery Journal | 米白、柔绿、大字号、低密度 | 放松、反焦虑 | 证据感不足；像健康 App | 不选 |
| **C. Dusk Ledger** | **暮色深蓝、纸张暖白、薄荷绿、琥珀时间线** | **开发者证据感与收工情绪兼得** | 需要精细控制色彩，避免做成普通 dark dashboard | **推荐** |

## 4. 推荐方案：Dusk Ledger / 黄昏证据簿

### 4.1 视觉世界

- **世界**：一天工作结束前，终端窗口旁的一本证据簿。
- **材质**：深色磨砂屏幕、纸张色日报、终端等宽标记、日落后的天空刻度。
- **签名元素**：贯穿今日页的 **“收工刻度”**——一条 04:00 → 次日 04:00 的横向时间轴，清楚分开真人 hands-on、agent 自主运行和 commit 落点。
- **大胆之处只放一个**：主结论文案与收工刻度组合成全页视觉中心；其余卡片保持安静。

### 4.2 色彩

| Token | 色值 | 用途 |
| --- | --- | --- |
| `night-950` | `#0D141C` | 主背景，带蓝的夜色而非纯黑 |
| `night-900` | `#151E28` | 卡片与侧栏 |
| `paper-100` | `#F3F0E8` | 主文字、日报纸张模式 |
| `mist-400` | `#93A0AD` | 次级文字、坐标与边界 |
| `mint-400` | `#62D6A7` | “够了”、已验证、hands-on |
| `amber-400` | `#F4B65F` | agent 自主运行、待解释证据 |
| `coral-400` | `#EF786F` | 仅用于真正缺口，不用于压力信号 |

颜色语义必须稳定：薄荷绿是“证据成立”，琥珀是“机器仍在运行或需要注意”，珊瑚红只表示可行动缺口。

### 4.3 字体

- 中文界面：`Noto Sans SC`，字重 400 / 500 / 700。
- 数据、时间、branch、commit：`IBM Plex Mono`。
- 主结论不用另加装饰字体，靠 56–72px 字号、紧字距和短句建立品牌性格。
- 数字统一使用 tabular numbers，时间轴与证据列表不会跳动。

## 5. 今日页布局

```text
┌──────────────┬─────────────────────────────────────────────────────┐
│ GOULE        │  8 月 29 日 · 周六              核验 | 日报         │
│              ├───────────────────────────────────┬─────────────────┤
│ 今天         │                                   │ 今日证据        │
│ 历史         │  够了，到点下班                   │ 5 commits       │
│ 规则         │  今天已完成 2 个主题，             │ 3 sessions      │
│ 设置         │  真人投入 2h35m。                  │ 2 repos         │
│              │                                   │ [复制日报]      │
│ Local only   ├───────────────────────────────────┴─────────────────┤
│ ● 数据已更新 │  收工刻度  04 ───── 12 ───── 18 ───── 24 ─── 04   │
│              │  hands-on    ▰▰  ▰▰▰       ▰                     │
│              │  agent       ▱▱▱▱▱▱   ▱▱▱▱▱▱▱                    │
│              │  commits          ◆  ◆        ◆◆                  │
│              ├───────────────────────────────┬─────────────────────┤
│              │ 证据账本                      │ 今天可以少做一点  │
│              │ goule / main                  │ 昨天恢复窗较短，   │
│              │ 2 sessions → 3 commits        │ 今天的门槛已下调。 │
│              │                               │ 查看依据           │
│              │ as-goapi / feature/...        │                     │
│              │ 1 session → 2 commits         │                     │
└──────────────┴───────────────────────────────┴─────────────────────┘
```

### 首屏信息顺序

1. **主结论 / 事实标题**：Phase 1 显示“今天发生了这些”；Phase 2 切换为 verdict 文案。
2. **一句解释**：只说最重要的 1–2 个原因，不堆规则名。
3. **收工刻度**：整合 hands-on、agent 与 commit，成为全产品最有辨识度的组件。
4. **证据账本**：按 repo / branch 聚合 session → commit；未归因项明确保留。
5. **恢复理由**：只用自然语言表达压力信号，默认不展示 debt 数字。

## 6. 核心组件

### Verdict Hero

- 不使用圆形得分环。
- GO 状态以大字号“够了，到点下班”为主，不铺满绿色背景。
- CAUTION / NO_GO 仍保持夜色背景，仅改变细线与关键动词颜色，避免警报感。
- Phase 1 没有 verdict 时，标题为“今天发生了这些”，底部标注“事实层 · 未启用规则判断”。

### Clock-out Scale / 收工刻度

- 24 小时单轴，逻辑日从 04:00 开始。
- 实心薄荷块：hands-on；半透明琥珀线：agent；菱形：commit。
- hover 同时高亮关联 session、repo 和 commit，不显示源码或对话正文。
- 23:00–06:00 使用极轻的夜间网纹，而不是红色危险区。

### Evidence Ledger / 证据账本

- 每行是 `repo / branch`，第二行写“2 sessions → 5 commits · hands-on 46m”。
- 展开后才显示 session 标题、commit subject 和归因方式 `exact / heuristic`。
- `unattributed` 永远作为独立行出现，不静默丢弃，也不用红色羞辱用户。

### Recovery Note / 恢复理由

- 标题用“今天可以少做一点”或“你的节奏很稳定”。
- 正文使用可审计事实：“昨天最后一次操作在 01:20，恢复窗 6h40m”。
- debt、权重、P90 放到“查看依据”抽屉，不放首屏。

### Dual-face Switch / 双模切换

- 顶部只保留“核验 / 日报”两段切换，不跳转到另一套导航。
- 切换日报后，证据账本原地变成纸张色 Markdown 预览，右侧变为编辑区。
- 复制成功后按钮文字变为“已复制”，不弹夸张 toast。

## 7. 交互与动效

- 首次进入只做一次 500–700ms 的时间轴绘制；支持 `prefers-reduced-motion`。
- 所有卡片 hover 只改变边框亮度和 1–2px 位移，不使用浮夸发光。
- 键盘快捷键：`T` 今天、`R` 日报、`C` 复制、`[` / `]` 前后一天、`⌘K` 命令面板。
- 移动端侧栏收进底部导航，收工刻度可横向拖动；核心结论与复制动作保持首屏可见。

## 8. 明确避免

- 生产力分数圆环、压力分数、排行榜、streak 火焰。
- 饼图和雷达图；它们既难比较，也会制造“优化自己”的暗示。
- 纯黑 + 荧光绿的泛 AI 风格。
- 大面积渐变、玻璃拟态层层叠叠、每张卡片不同颜色。
- 将 agent minutes 与 hands-on 相加或并排写成“总工时”。
- 用“超标、落后、效率低”描述恢复和压力信号。

## 9. 实现优先级

1. **P0**：Today shell、Verdict Hero 的 Phase 1 状态、收工刻度、证据账本。
2. **P1**：核验 / 日报切换、Markdown 预览与复制、详情抽屉。
3. **P2**：历史页、命令面板、主题切换和导出分享图。

首个高保真原型只需覆盖 1440px 桌面端的 Today 页，使用真实 `scanDay` 数据。先把签名组件“收工刻度”做对，再扩展其他页面。
